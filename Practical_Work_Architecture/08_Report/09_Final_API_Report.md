# GamesJustLike — итоговый отчёт по практике (REST API + MySQL)

## 1. Цель и краткое описание проекта

GamesJustLike — учебный интернет-магазин компьютерных игр с тёмным оформлением в стиле Steam. В рамках практики требовалось:

- вынести все данные магазина в отдельный REST API на PHP (обмен по HTTP + JSON);
- перенести базу данных из SQLite в MySQL;
- перевести работу сайта на API — без прямых SQL-запросов к основной БД;
- реализовать авторизацию пользователей;
- реализовать персональные рекомендации и похожие игры;
- сохранять пользовательские события (view, cart_add, purchase);
- использовать матрицы предпочтений и связей между играми.

## 2. Архитектура

Схема работы:

    Браузер -> Сайт (PHP, C:\xampp\htdocs\GamesJustLike-site)
                  |
                  | config/api_client.php -> apiRequest()
                  | (HTTP + JSON, Bearer Token)
                  v
               REST API (PHP, C:\projects\shop-data-api)
                  |
                  | config/database.php -> PDO
                  v
               MySQL 8 (порт 3307, БД gamesjustlike)

Ключевые принципы:

- Сайт не обращается к MySQL напрямую. Проверено поиском по всем PHP-файлам сайта (исключая config/, data-api/, old_tools/, Practical_Work_Architecture/, database/): вхождений new PDO, mysqli_*, mysql_*, getDatabaseConnection не найдено.
- Все запросы к данным идут через единый клиент config/api_client.php (apiRequest()), который сам подставляет Bearer Token и возвращает уже распакованное поле data.
- API-сервер запускается отдельно: php -S 127.0.0.1:8081 -t public из C:\projects\shop-data-api.
- Внутри сайта лежит актуальная копия API: C:\xampp\htdocs\GamesJustLike-site\data-api (синхронизация проверена по SHA256 — все файлы идентичны).

## 5. Авторизация

- Сайт использует сессию PHP ($_SESSION[user_id]) для входа пользователя.
- Каждый запрос сайта к API подписывается заголовком Authorization: Bearer <token>.
- Токен хранится на стороне сайта в config/api_client.php (константа SHOP_API_TOKEN) и не передаётся в браузер.
- API сверяет токен через hash_equals с эталоном из config/config.php.
- Проверено: без заголовка Authorization API возвращает HTTP 401.

## 6. Пользовательские события

Цепочка обработки события:

1. Пользователь нажимает кнопку на странице игры (js/user_events.js).
2. JS отправляет POST на api/event.php с product_id и event_type (view / cart / purchase).
3. api/event.php проверяет $_SESSION[user_id], нормализует cart -> cart_add, генерирует event_key на сервере (random_bytes).
4. api/event.php вызывает apiRequest(events.php, POST, ...) — то есть идёт через API, без прямых SQL.
5. events.php пишет событие в таблицу user_events (MySQL ON DUPLICATE KEY UPDATE по event_key защищает от дублей).
6. Событие учитывается в рекомендациях (eventsScore, вес 0.05 в итоговой формуле).

Поддерживаемые типы событий: view, cart_add, purchase.


## 7. Матрицы предпочтений и связей

В MySQL используются четыре вида матриц:

| Матрица | Таблица | Смысл |
|---|---|---|
| Игра — предпочтение | product_preferences | Насколько игра соответствует каждому предпочтению (коэффициент 0..1) |
| Игра — игра | product_relations | Связи между играми: similar (похожие) и другие типы, с коэффициентом |
| Группа — предпочтение | group_preferences | Предпочтения, характерные для группы покупателей |
| Группа — категория | group_categories | Категории, интересные группе покупателей |

Все матрицы отдаются эндпоинтом product-matrices.php (ключи product_preferences и product_relations).

## 8. Персональные рекомендации и блок на главной

Алгоритм реализован в config/recommender.php, функция computeRecommendations(?int $userId, bool $includeUnavailable = false).

Итоговый рейтинг игры:

    0.40 * personal + 0.25 * groupScore + 0.15 * relScore + 0.15 * baseline + 0.05 * eventsScore

Где:

- personal — совпадение предпочтений пользователя (user_preferences);
- groupScore — предпочтения группы пользователя (group_preferences);
- relScore — связи между играми (product_relations);
- baseline — базовые предпочтения (product_preferences);
- eventsScore — история событий пользователя (user_events).

На главной странице (index.php) вызывается $items = computeRecommendations($userId), и над каталогом выводится отдельный визуальный блок "✨ Рекомендуем для вас" (топ-6 игр). Существующий каталог, поиск, сортировка и сравнение при этом не изменяются.


## 9. Похожие игры на странице товара

На странице product.php внизу, под карточкой игры, выводится блок "🎮 Похожие игры". Логика:

1. Через apiRequest(product-matrices.php) получаем массив product_relations.
2. Оставляем только строки, где source_product_id = ID текущей игры и relation_type = similar.
3. Сортируем по coefficient по убыванию и берём первые 6.
4. Данные игр (обложка, название, цена) берём из уже полученного на странице массива $products (без дополнительных запросов).
5. Каждая карточка ведёт на product.php?id=ID.
6. Если связей нет — блок не выводится.

Пример: для игры ID 1 (Cyberpunk 2077) в product_relations есть связи similar с ID 2, 4, 21 (coefficient = 0.55). Все три игры отображаются в блоке.
