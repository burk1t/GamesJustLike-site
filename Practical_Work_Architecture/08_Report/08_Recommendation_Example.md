
# Числовой пример изменения рекомендаций GamesJustLike

## 1. Исходные данные

Пользователь: User01.

Индивидуальные предпочтения:

| Предпочтение | Начальный коэффициент |
|---|---:|
| RPG | 0.95 |
| Шутеры | 0.30 |
| Стратегии | 0.70 |

## 2. Событие пользователя

Пользователь добавил RPG-игру в корзину.

Тип события: add_to_cart.

Вес события: +4.

## 3. Правило обновления

Для учебной модели используется формула:

Новый коэффициент = старый коэффициент + вес события × 0.01.

Минимальное значение — 0.00.
Максимальное значение — 1.00.

## 4. Расчёт

RPG: 0.95 + 4 × 0.01 = 0.99.

Остальные предпочтения не изменяются.

## 5. Результат

| Предпочтение | До события | После события |
|---|---:|---:|
| RPG | 0.95 | 0.99 |
| Шутеры | 0.30 | 0.30 |
| Стратегии | 0.70 | 0.70 |

## 6. Изменение рекомендаций

До события система учитывала RPG с коэффициентом 0.95.

После добавления игры в корзину коэффициент RPG увеличился до 0.99.

Поэтому RPG-игры получают более высокий приоритет при формировании персональной подборки.

## 7. Где выполняется расчёт

Расчёт выполняется на сервере в модуле предпочтений и рекомендаций.

Сервер получает событие, проверяет пользователя и игру, обновляет запись в user_preferences и передаёт обновлённые данные модулю рекомендаций.

Браузер получает готовый список рекомендаций и отображает его пользователю.
